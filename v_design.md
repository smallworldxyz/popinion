> *"The goal isn't to be right. It's to become less wrong."*

## The Core Philosophy

**"Become less wrong."**

No single perspective is complete. No simulation captures the full truth. Popinion V is built on three foundational principles:

| Principle | What It Means |
|-----------|---------------|
| **Epistemic Humility** | Your worldview has blind spots you can't see alone |
| **Adversarial Testing** | Ideas strengthen when they survive opposition |
| **Collective Intelligence** | Many perspectives > single perspective |

Popinion V enables users to stress-test their understanding against others — not to prove they're right, but to discover what they're missing. Every feature is designed to surface hidden weaknesses, inject missing perspectives, and synthesize stronger positions.

---

## The Problem

Today, each Popinion user builds an **isolated graph**:
- Their own sources, their own entities, their own agents
- Blind spots they don't know exist
- Simulations limited by a single worldview
- No mechanism to challenge assumptions with opposing views

**The result**: Users confirm what they already believe instead of discovering what they're missing.

**What if you could overlay your graph with others? What if every simulation included built-in opposition?**

---

## How We Solve It

Popinion V attacks the problem from two directions:

### 1. Graph Fusion (Multi-User)
Merge knowledge graphs to gain perspectives you're missing → *The Four-Phase Model*

### 2. Deep Interaction Tools (Single-User)
Stress-test ideas against your own agents through structured debate and collective polling → *Agora, Panel Chat, Knowledge Pad*

Both approaches serve the same philosophy: **become less wrong by exposing your ideas to opposition.**

## The Four-Phase Model

### Phase 1: Enrichment (Additive Mode)
> *"What am I missing?"*

User A has a graph about **Economic Policy**. User B has a graph about **Labor Demographics**. Neither alone sees the full picture.

When B's graph is layered onto A's:
- New entities appear (labor unions, migrant workers)
- New relationships emerge (how policy affects labor mobility)
- A's simulation gains **agents that wouldn't have existed** in the original graph

**This isn't adversarial — it's collaborative knowledge building.**

Key Feature: Detect **conflicting claims** before merging. Present "perspective tensions" that need resolution.

---

### Phase 2: Convergence (Readiness Check)
> *"Do we see the same reality?"*

Before enabling adversarial mode, detect overlap:

| Metric | Description |
|--------|-------------|
| **Entity Overlap** | Shared entities between graphs |
| **Topic Similarity** | Semantic theme alignment |
| **Stance Divergence** | Opposing views on shared topics |

When convergence is sufficient + stance divergence detected:
→ *"Graphs are ready for adversarial testing"*

---

### Phase 3: Adversarial (A vs. B Mode)
> *"Where do we break?"*

Both graphs share enough common ground. Now they clash:

- **Policy Testing**: A's policy agents vs. B's opposition agents
- **Narrative Clash**: A's media narrative vs. B's counter-narrative
- **Faction Simulation**: Government (A) vs. Civil Society (B)

Output: Predictions with **tension built-in**.

---

### Phase 4: Synthesis (New Understanding)
> *"What's the stronger position?"*

After adversarial testing:
- Where did A's arguments fail?
- What did B reveal that A couldn't counter?
- What's the **synthesized position** that incorporates both?

This generates **new knowledge** — not just wins/losses.

**The cycle repeats**: Synthesis becomes the new Graph A', ready for further enrichment.

```
ENRICHMENT → CONVERGENCE → ADVERSARIAL → SYNTHESIS
     ↑                                        │
     └────────────────────────────────────────┘
```

## Deep Interaction Enhancements

Beyond one-on-one agent interviews, Popinion V introduces **collective interaction modes** — the single-user implementation of our core philosophy.

> **How these features serve "Become Less Wrong":**
> - **Agora** → Forces ideas to survive structured opposition (adversarial testing)
> - **Panel Chat** → Reveals factional fault lines you didn't expect (blind spot detection)
> - **Knowledge Pad** → Injects missing perspectives into agents (collective intelligence)
> - **Surveys** → Quantifies sentiment before/after to measure understanding shifts

These tools don't require multi-user graph fusion — they let you stress-test ideas against your own simulated society.

### 🏛️ Agora: Structured Debate Arena

> *"Where ideas clash and truth emerges."*

Agora is a **moderated debate system** that orchestrates structured, multi-round discussions between agents. Unlike casual interviews, Agora creates adversarial tension by design — forcing agents to defend positions, counter arguments, and reveal the weaknesses in ideas.

**Debate Goal Types:**

| Goal | Icon | Description | Best For |
|------|------|-------------|----------|
| **Point-Counterpoint** | 🎯 | Stress-test a decision from all angles | Testing policy proposals |
| **Devil's Advocate** | ⚠️ | Identify risks, blind spots, worst-case scenarios | Risk assessment |
| **Stakeholder Caucus** | 👥 | Understand each group's concerns and priorities | Multi-faction negotiations |
| **Red Team / Blue Team** | ⚔️ | Competitive analysis between opposing groups | Strategic planning |
| **Consensus Building** | 🤝 | Find middle ground and shared values | Conflict resolution |
| **Socratic Drill** | 🔍 | Expose hidden assumptions through questioning | Deep analysis |

**How It Works:**

1. **Setup**: Select debate goal, topic, and agents (min 2)
2. **Configure**: Set rounds (3-10), mode (continuous/reviewed), round duration
3. **Execute**: Agents debate in timed rounds, each responding to previous arguments
4. **Monitor**: Real-time stance tracking, timeline charts, turn-by-turn transcript
5. **Summarize**: AI-generated summary of key points, consensus areas, and unresolved tensions

**Unique Features:**

- **Live Streaming**: Watch agents respond in real-time during timed rounds
- **Stance Visualization**: Track how each agent's position shifts across rounds
- **Pivot Topics**: Inject new angles mid-debate to steer discussion
- **Round Summaries**: AI-generated recap after each round
- **Highlight to Knowledge Pad**: Select key quotes and add them directly to your notes

**Strengths:**

| Strength | Why It Matters |
|----------|----------------|
| **Structured adversarial testing** | Forces ideas to defend against active opposition |
| **Multi-perspective collision** | Surfaces tensions between stakeholder groups |
| **Traceable stance evolution** | See exactly when and why positions shift |
| **Exportable insights** | JSON export for further analysis |

**Best Use Cases:**
- Stress-testing policy proposals before real-world announcement
- Simulating negotiation outcomes before entering the room
- Identifying which stakeholder concerns are hardest to address
- Discovering blind spots in your own reasoning

### 💬 Panel Chat: Collective Voice

> *"What does the room think?"*

Panel Chat provides **instant polling of your entire agent population**. Instead of interviewing agents one by one, ask a question to all agents simultaneously — like addressing a panel of experts.

**How It Works:**

1. User poses a question: *"What are your views on the new economic policy?"*
2. All selected agents (or all 35) respond in parallel
3. Responses are aggregated and displayed:
   - **By stance**: Group supporters vs. critics vs. neutral
   - **By faction**: Government officials vs. civil society vs. business
   - **By theme**: Economic concerns vs. political concerns vs. social impacts

**Key Features:**

- **Stance Classification**: AI automatically classifies each response (support/oppose/neutral)
- **Faction Grouping**: Responses grouped by agent type/role for demographic analysis
- **Summary Generation**: AI synthesizes the overall sentiment and key disagreements
- **Profile-Based Fallback**: Works even without active simulation environment

**Strengths:**

| Strength | Why It Matters |
|----------|----------------|
| **Speed** | Get 35 opinions in seconds vs. hours of individual interviews |
| **Pattern detection** | Instantly see factional alignments and outliers |
| **Quantifiable sentiment** | Stance percentages provide measurable data |
| **Low commitment** | Quick pulse-check without formal debate setup |

**Output Options:**
- Individual responses (expanded view)
- Summarized consensus/dissent report
- Stance distribution chart with percentages

**Best Use Cases:**
- Quick pulse check on a controversial topic
- Identify fault lines in the simulated society
- Discover unexpected alliances or oppositions
- Pre-debate reconnaissance to identify most polarizing issues

#### Left Panel: Knowledge Pad (Agent-Captured)

> *"What did we learn from the simulation?"*

| Feature | Description |

| **Tag System** | Organize with predefined + custom tags (key_insight, evidence, quote, etc.) |

#### Right Panel: Knowledge Gaps (User-Authored)

> *"What's missing that we need to add?"*

This is where the **user** identifies gaps that the simulation didn't surface — perspectives, relationships, or facts that should exist but don't.

**Add Gap Form:**

| Field | Description |
|-------|-------------|
| **Missing Knowledge** | Free-text description of what's absent |
| **Attribute To** | Which agent should receive this knowledge (or "Global" for all agents) |
| **Tag** | Categorize: `missing_perspective`, `missing_relationship`, `missing_stakeholder`, `counter_argument`, etc. |

**Example Gap Entries:**
- *"No labor union perspective represented"* → Attribute: Global → Tag: `missing_stakeholder`
- *"Agent X doesn't account for environmental impact"* → Attribute: Agent X → Tag: `missing_perspective`
- *"Government-NGO partnership not reflected"* → Attribute: Global → Tag: `missing_relationship`

### Send Survey to Simulation World

> *"Mass polling the digital mirror."*

Deploy structured surveys to agents — not just open-ended questions, but **formatted questionnaires** with measurable responses.

**Survey Types:**

| Type | Description |
|------|-------------|
| **Opinion Poll** | Single question, multiple choice (Agree/Disagree/Neutral) |
| **Likert Scale** | Rate agreement 1-5 on a statement |
| **Ranking** | Rank options by preference |
| **Open Response** | Free-form answers (analyzed for themes) |

**Workflow:**

1. **Create Survey**: Define questions and response format
2. **Select Targets**: All agents, or filter by type (e.g., only Government officials)
3. **Deploy**: Agents respond based on their persona and memory
4. **Analyze**: Aggregated results with breakdowns by faction, stance, demographics

**Key Features:**
- **Before/After Comparison**: Run same survey pre- and post-simulation to measure shift
- **Cross-Segment Analysis**: Compare responses between factions
- **Export**: Download results as CSV/JSON for external analysis

**Example Use Case:**
> *"Survey all agents: 'Would you support a 10% increase in minimum wage?'"*  
> Results: 60% support (mostly labor groups), 25% oppose (business leaders), 15% neutral

## 🔍 Graph Verification: Quality Gate Before Simulation

> *"Verify before you simulate. Fix before you fail."*

The Graph Verification step is an **optional quality gate** between Graph Building (Step 1) and Environment Setup (Step 2). It allows users to review, verify, and correct the knowledge graph before agents are generated from it.

### Where It Fits

```
┌──────────────────────────────────────────────────────────────────────────────┐
│                              POPINION WORKFLOW                               │
├──────────────────────────────────────────────────────────────────────────────┤
│                                                                              │
│  STEP 1              STEP 1.5 (NEW)         STEP 2             STEP 3       │
│  ┌─────────┐        ┌─────────────┐        ┌─────────┐        ┌─────────┐   │
│  │ GRAPH   │   →    │   GRAPH     │   →    │  ENV    │   →    │  SIM    │   │
│  │ BUILD   │        │   VERIFY    │        │  SETUP  │        │  RUN    │   │
│  └─────────┘        └─────────────┘        └─────────┘        └─────────┘   │
│                            │                                                 │
│                     "Looks Good"  OR  "Needs Work"                           │
│                            ↓              ↓                                  │
│                     Proceed         Edit / Enrich                            │
└──────────────────────────────────────────────────────────────────────────────┘
```

### The Decision Point

| If Graph "Looks Good" | If Graph "Needs Work" |
|-----------------------|------------------------|
| Proceed to Step 2 | Choose a remedy path |
| Agents generated from current graph | Graph improved before agent generation |

### "Needs Work" Options

When the graph doesn't look right, the user has multiple paths:

| Option | What It Does | When To Use |
|--------|--------------|-------------|
| **Edit Entity** | Modify entity name, type, or attributes | Wrong name, wrong classification |
| **Delete Entity** | Remove irrelevant or incorrect entities | Noise in the graph |
| **Add Entity** | Manually create missing stakeholders | Key player absent |
| **Edit Relationship** | Modify connection between entities | Wrong relationship type |
| **Add Relationship** | Create new connections | Missing links |
| **Inject Knowledge** | Import Knowledge Gaps as graph facts | User-identified gaps |
| **Add More Sources** | Upload additional documents mid-flow | Need more context |
| **Regenerate Ontology** | Re-run Step 1 with different parameters | Schema fundamentally wrong |

## 🔄 Iterative Refinement: The Core Loop

> *"You often don't know what's missing until you see agents fail to account for it."*

The Iterative Refinement Loop is the **operational manifestation** of Popinion's core philosophy. Every simulation run is not an end — it's a **diagnostic opportunity** that feeds the next, better simulation.

### The Principle

**Perfection before simulation is impossible** because:
- You can't predict every stakeholder perspective upfront
- Graphs built from documents inherit document blind spots
- Real complexity only surfaces when agents interact

**The solution**: Build a "good enough" graph → Run simulation → Use simulation to expose weaknesses → Feed corrections back → Run again.

### The Complete Cycle

```
┌────────────────────────────────────────────────────────────────────────────────────────┐
│                         THE ITERATIVE REFINEMENT LOOP                                  │
├────────────────────────────────────────────────────────────────────────────────────────┤
│                                                                                        │
│     ┌─────────────┐      ┌─────────────┐      ┌─────────────┐      ┌─────────────┐    │
│     │   BUILD     │      │   RUN       │      │  DISCOVER   │      │   REFINE    │    │
│     │   GRAPH     │ ───→ │   SIM       │ ───→ │   GAPS      │ ───→ │   GRAPH     │    │
│     └─────────────┘      └─────────────┘      └─────────────┘      └─────────────┘    │
│            ↑                                                              │            │
│            └──────────────────────────────────────────────────────────────┘            │
│                                                                                        │
│                    Each cycle produces a LESS WRONG simulation                         │
└────────────────────────────────────────────────────────────────────────────────────────┘
```

### Cycle Breakdown

| Phase | What Happens | Tools Used |
|-------|--------------|------------|
| **BUILD** | Create knowledge graph from sources | Graph Builder, Ontology Generator |
| **VERIFY** | (Optional) Check graph quality | Graph Verification |
| **SIMULATE** | Run agents, observe interactions | Simulation Runner |
| **INTERACT** | Deep dive into agent perspectives | Panel Chat, Agora, Surveys |
| **CAPTURE** | Record insights from simulation | Knowledge Pad (left panel) |
| **IDENTIFY** | Note missing perspectives | Knowledge Gaps (right panel) |
| **INJECT** | Push gaps into next simulation | Knowledge Injection |
| **REFINE** | Edit graph based on discoveries | Graph Verification (edit mode) |
| **REPEAT** | Run again with improved foundation | — |

### What Each Turn Produces

| Turn | What You Learn | What Improves |
|------|----------------|---------------|
| **1st** | Major blind spots surface | Add missing stakeholders |
| **2nd** | Relationship gaps appear | Add missing connections |
| **3rd** | Nuance issues emerge | Refine agent perspectives |
| **4th+** | Diminishing gaps | Approaching "less wrong" |

### Exit Conditions

The loop continues until:
- **Confidence threshold**: No major gaps discovered in last N runs
- **Time constraint**: User decides current state is good enough
- **Synthesis complete**: All major perspectives have been stress-tested

### How This Serves "Become Less Wrong"

| Philosophy Principle | How Iterative Refinement Implements It |
|---------------------|---------------------------------------|
| **Epistemic Humility** | Assumes first graph is incomplete |
| **Adversarial Testing** | Uses simulation to reveal weaknesses |
| **Collective Intelligence** | Incorporates user + agent + graph knowledge |
